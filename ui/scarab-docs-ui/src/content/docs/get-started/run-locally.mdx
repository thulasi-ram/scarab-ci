This page gets the whole stack running on your machine and pushes a pipeline through it. One
command (a `Justfile` over `deploy/kind/`) builds `scarab-server` from the tree and runs it inside a
local kind cluster from the Helm chart, so you can rebuild and rerun without building an image. To deploy the packaged chart
instead (on kind or a live cluster), see [Installation](/scarab-ci/get-started/deploy-helm/);
the [Overview](/scarab-ci/get-started/overview/) compares the two paths.

If you would rather look before you install, the [live demo](https://demo-scarab.ahiravan.dev/)
is a running instance. It is read-only for visitors, so it shows you the UI but will not run your
pipeline. The steps below run Scarab on your machine.

## Prerequisites

- **docker**, **kind**, **kubectl**, **helm**: the stack runs in a local kind cluster.
- **cargo** (Rust toolchain, see `rust-toolchain.toml`): the server is built from source. On macOS
  also **zig** and **cargo-zigbuild**, which build the Linux binary the cluster runs.
- **python3**: the demo submits a pipeline over the REST API.
- [`just`](https://github.com/casey/just): the task runner.

## Bring up the stack

```sh
just stack up  # kind + Postgres + MinIO + the chart, server built from the tree
```

`just stack up` builds `scarab-server` for Linux, creates the `scarab-dev` kind cluster, starts Postgres
and MinIO in it, and installs the Helm chart. The server and the workspace service run the binary
you just built, mounted into a small runtime image. The API and the UI answer on `SCARAB_ADDR`
from `deploy/kind/.env`.

## Submit a pipeline and watch it complete

```sh
just stack demo  # submit a one-step pipeline and watch it run to completion
```

This posts a pipeline to the running server and follows it until it finishes. It's the smallest
end-to-end run, and it survives you killing the control plane partway through.

## Iterate

```sh
just stack reload  # rebuild and roll the server onto the new binary
just stack logs    # follow the server's log
just docs          # serve this documentation site locally
just stack down    # tear the whole stack down (`just stack down keep` keeps the data)
```

:::note[Tests]
`just test e2e` runs every live suite against the same release, switched to its e2e mode with its
own database and bucket. `just stack up` switches it back.
:::

:::tip[See the UI]
`just ui` starts the SolidJS web UI (Vite on <code>http://localhost:5173</code>), which proxies
`/v1` to the running server. Open a run to see its step DAG and event timeline, which refresh
while the run is going, and each step's logs, which stream live over SSE. To look around
without a server, `just ui mock` renders the same UI from built-in fixtures.
:::

## What just happened

The server wrote every step transition to Postgres, where the run lives as a durable state
machine. Kill the control plane mid-run and bring it back. The run resumes from where it
stopped instead of starting over. That is the main guarantee Scarab makes.
