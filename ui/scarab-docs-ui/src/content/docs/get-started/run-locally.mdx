The repo ships a one-command dev harness (a `Justfile` over `deploy/local-proc/`) that runs
`scarab-server` straight from the tree, giving you a rebuild-and-run loop with no image to
publish. It runs the durable core end-to-end on your machine. To deploy the packaged chart
instead — on kind/colima or a live cluster — see [Installation](/scarab-ci/get-started/deploy-helm/);
the [Overview](/scarab-ci/get-started/overview/) compares the two paths.

## Prerequisites

- **docker**, **kind**, **kubectl** — the stack runs `scarab-server` against a local kind cluster.
- **cargo** (Rust toolchain, see `rust-toolchain.toml`) — the server is built from source.
- **python3** — the demo submits a pipeline over the REST API.
- [`just`](https://github.com/casey/just) — the task runner.

## Bring up the stack

```sh
just up      # Postgres + MinIO + kind + scarab-server (background)
```

`just up` starts Postgres and MinIO (via `deploy/local-proc/compose.yaml`), creates a kind cluster
(`deploy/local-proc/kind.yaml`), and runs `scarab-server` in converged mode against them.

## Submit a pipeline and watch it complete

```sh
just demo    # submit a one-step pipeline and watch it run to completion
```

This posts a pipeline to the running server and follows it to a terminal state — the walking
skeleton that survives a mid-run control-plane kill.

## Iterate

```sh
just serve   # run scarab-server in the FOREGROUND against the dev stack (Ctrl-C to stop)
just logs    # tail the background server log
just docs    # serve this documentation site locally
just down    # tear the whole stack down
```

:::note[The other mode: in-cluster Helm]
`just up` runs the server as a host process (kind for step Pods). For the real in-cluster path —
`scarab-server` deployed via the Helm chart on colima, with in-cluster Postgres + MinIO — use
`just local-helm` (`just local-helm local` builds from the tree; `just local-helm sha-<sha>` pins a
published build). See [Installation](/scarab-ci/get-started/deploy-helm/).
:::

:::tip[See the UI]
`just ui` starts the SolidJS web UI (Vite on <code>http://localhost:5173</code>), which proxies
`/v1` to the running server. It's an early scaffold today — the rich live-DAG / SSE-logs UI is a
follow-up.
:::

## What just happened

The server persisted every step transition to Postgres as a durable state machine. Kill the
control plane mid-run and bring it back — the run resumes from where it stopped rather than
restarting. That durability contract is the whole point.
