Scarab treats a pipeline as a **resumable, inspectable, mutable-mid-flight workflow**. Because the
orchestrator is a crash-safe durable state machine on Postgres, **resume**, **restart-a-step**,
**time-travel**, and long-lived **approval gates** are native — not bolted on.

![The Scarab control plane — live DAG, SSE logs, time-travel (placeholder)](../../assets/screenshot-placeholder.svg)

## The wedge

<CardGrid>
  <Card title="Durable by construction" icon="approve-check">
    A DBOS-pattern durable state machine on Postgres. A mid-run control-plane kill resumes exactly
    where it left off — durability is the product, not a feature.
  </Card>
  <Card title="Kubernetes-native" icon="puzzle">
    Pod-per-step execution on a content-addressed workspace (per-file merkle CAS). k8s-only, no
    bespoke runner fleet to babysit.
  </Card>
  <Card title="Forge-integrated, keyless" icon="seti:lock">
    Forge-agnostic OIDC identity, with Scarab itself as an OIDC issuer for keyless federation to
    your cloud.
  </Card>
  <Card title="A real DSL" icon="seti:config">
    A typed IR (the actual DSL) with a YAML frontend and CEL expressions — a flat recursive DAG
    where <code>invoke</code> is reuse and matrix is a modifier.
  </Card>
</CardGrid>
